# Architecture Decision Records (ADRs)

## ADR-001: Modular Monolith with Node.js Built-in SQLite (`node:sqlite`) and Vitest
- **Context:** We need a fast, zero-external-dependency, reproducible evaluation laboratory with ACID transactions, unique slot constraints, and deterministic snapshots.
- **Decision:** Use TypeScript in strict mode, Node 22 built-in `node:sqlite` (`DatabaseSync`), `zod` for schema enforcement, and `vitest` for test orchestration.
- **Alternatives Considered:** External PostgreSQL container (adds Docker runtime dependency and network flakiness), in-memory JS Maps (lacks real SQL transactional rollback and unique index enforcement).
- **Tradeoffs:** `node:sqlite` is synchronous and single-process, which maximizes determinism and speed (<2s full suite execution) without requiring external daemons.

## ADR-002: Backend-Enforced Patient-Scoped Verification Tokens
- **Context:** Prompt instructions alone cannot prevent a compromised or hallucinating LLM agent from invoking mutation tools without caller verification (`INV-01`, `INV-06`).
- **Decision:** `VerificationService` issues opaque `VerificationSession` tokens stored in SQLite and bound to `(conversationId, patientId, expiresAtMs)`. Every mutation transaction in `AppointmentRepository` validates the token inside `BEGIN IMMEDIATE ... COMMIT`.
- **Alternatives Considered:** Boolean `isVerified` flag passed by the agent (trivially spoofable by prompt injection or agent bug).
- **Tradeoffs:** Requires explicit token lifecycle management (issuance, expiration, and revocation on identity switch), which directly enables deterministic testing of `T02`, `T06`, `T16`, and `T17`.

## ADR-003: Strict Separation of Independent Observer from Agent Runtime
- **Context:** Self-evaluating agents or harnesses that inspect only HTTP status codes produce false positives when responses are spoofed (`T18`), claims are hallucinated (`T10`–`T12`), or audit events are missing.
- **Decision:** `IndependentObserver` receives deep-frozen pre/post database snapshots, backend audit logs, and transport traces after execution finishes. It has zero write access to the database (`INV-09`) and never uses agent text as ground truth for backend state.
- **Alternatives Considered:** Inline assertions inside the agent loop (couples observation with execution and cannot catch post-turn inconsistencies).
- **Tradeoffs:** Requires maintaining full provenance tags (`AGENT_TRACE`, `TOOL_TRANSPORT`, `BACKEND_AUDIT`, `DB_SNAPSHOT`), which increases schema surface but guarantees verifiable root-cause analysis.

## ADR-004: Deterministic Idempotency Keys and Read-Only Reconciliation for `UNKNOWN` Outcomes
- **Context:** When a mutation commits in SQLite but the response drops (`POST_COMMIT_DROP`, `T09`), retrying with a new idempotency key risks double-booking or confusing `SLOT_CONFLICT` errors (`INV-05`, `INV-08`).
- **Decision:** Mutations require an `idempotencyKey` and SHA-256 payload hash stored atomically with the appointment mutation. On `UNKNOWN` transport outcomes, the agent calls read-only `reconcileOperation(operationId, idempotencyKey)` or replays the exact same idempotency key. Reusing an idempotency key with mutated parameters is rejected with `IDEMPOTENCY_PARAMETER_MISMATCH`.

## ADR-005: Two-Level Voice Evaluation Architecture (Level 1 Deterministic Events Before Level 2 Audio)
- **Context:** Acoustic speech-to-text introduces non-deterministic noise, latency, and API cost, whereas conversation state bugs (barge-in during confirmation, partial-utterance premature execution, silence handling) are deterministic protocol errors.
- **Decision:** Implement Level 1 `VoiceEventSimulator` with controllable clock and turn-ownership state machine first (`T13`, `T14`, `T15`, `V01`–`V05`), and define an optional Level 2 `AudioProviderAdapter` boundary without claiming acoustic accuracy from Level 1 tests.
